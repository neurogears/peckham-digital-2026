What is Bonsai?

A language, an ecosystem, an editor

  • Open source, reactive programming language
  • Ecosystem of packages for hardware integration, graphics, and more
  • Visual editor for designing workflows
Bonsai is an open-source programming language, ecosystem and development environment. It was born and initially developed in the world of neuroscience research, where it aimed to solve some problems that are also relevant outside academic research.

Problem 2

Unified model for handling async data

Doing interesting things with hardware in real time is difficult, and it gets much more difficult the more hardware you have. Cameras, audio, projection, MIDI, machine learning: they all talk a different language in terms of transmission protocols, data formats and sampling rates. Bonsai aims to unify all these devices, so when you build an interactive, real-time system you think about the interactions between hardware rather than wrangling data formats and synchronisation.

The Bonsai model

Source

Produces a stream of data.
Camera frames, microphone buffers, key presses

Transform

One-to-one transformations.
Recolour an image, filter an audio buffer

Combinator

Combines or gates streams, usually two or more.
Sample on a key press, sync two streams

Sink

Does something with the data, passes it on unchanged.
Write to disk, send over the network
At a high level Bonsai is made of operators, nodes of processing that do one of a few things. Sources produce streams of data. Transforms are one-to-one transformations of a stream. Combinators are combinatorial and conditional operations, usually needing two or more streams: sample one stream whenever an event happens, or combine two for synchronisation. Sinks are side effects that don't modify the stream, for example writing data to disk. The colours match the node colours you will see in the editor.

Under the hood

Parallel by default

  • Built on Reactive Extensions (Rx) from Microsoft
  • Every stream is asynchronous and runs in parallel
  • No threads, locks or callbacks to manage: drop in a camera, a microphone, a keyboard, and it just runs
Technical aside: all of this is based on the Reactive Extensions library. Bonsai uses Rx to make these data streams parallel and asynchronous, but hides the set-up. As a user you don't write code to manage multithreading. You drop in camera, microphone, keyboard input, and it all runs in parallel out of the box.

Thinking in Bonsai

Parallel data flows and combinations

Because of this parallelism Bonsai lends itself to visual programming, and programs are built as branching observable sequences. If you've done functional programming it might feel familiar, but generally you think of a Bonsai program as asynchronous data flow rather than sequential instructions.
